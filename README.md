# H2S 五城市房源监控

Tampermonkey 脚本 **v1.3.12**：在打开的 Holland2Stay 房源列表页运行。保留 **Available to book**，不选 City，多页时自动选择 **Price**，从第一页按主租金扫描，在首次出现超预算房源的当前页读完后停止翻页。只通知目标五城、主租金在预算内、可直接预订的房源。默认预算为 €1000，可在菜单中保存自己的上限。

电脑需要联网、不休眠，并保持浏览器页面打开。GitHub 保存代码；推送更新不会自动替换已经安装的 Tampermonkey 脚本。

## 更新和立即检查

1. 用 [`h2s-monitor.user.js`](h2s-monitor.user.js) 的全部内容覆盖 Tampermonkey 中原有脚本，保存，再刷新 H2S 页面。确认面板版本为 **1.3.12**。
2. 保持英文界面，选择 **Available to book**。City 可留空，或手动选择一个目标城市。
3. **23:00–07:00 荷兰时间不自动开始扫描，也不自动点 Sort。** 夜间点击面板上的 **立即检查（夜间也可运行）**，或使用 Tampermonkey 同名菜单。
4. 手动调整筛选后会先等待 30 秒。启动扫描后先等房源列表稳定；确认有多页才尝试排序。无需反复点击。
5. 需要改预算时使用“设置预算（主租金上限）”；更新脚本后仍保留这个设置。首次使用本版且未保存预算时采用 €1000。

原脚本名称、namespace、Telegram 存储键和历史格式保持不变。直接覆盖原脚本即可保留配置和已成功通知记录；无需清除历史或强制重发。

## v1.3.12：容忍列表中残留的已租出房源

房源可能在两次刷新之间被租走，卡片已显示 **Occupied**，却仍留在 **Available to book** 列表中。旧版要求该列表内每套房源都可直接预订，因此把这种正常状态变化当作整轮扫描失败，连续发生时还会进入故障暂停。

现在对明确标记为 **Occupied** 的卡片继续读取，计入已读数量、分页完整性和价格顺序检查，但不计入符合数量，也不发送房源通知。面板显示“已跳过 N 套已租出房源（仍计入已读）”。整轮扫描通过后，这些房源的旧待发通知会被清除；以后再次变为可直接预订且符合预算时，仍会通知。全部卡片都已租出时，正常完成扫描，符合数量为 0。

仍需正确的城市、主租金、总数和稳定列表；缺字段、分页不完整、价格乱序，以及筛选后残留的抽签或未知状态继续等待或报错。刷新间隔仍为 5–15 分钟，不能补抓在两次检查之间出现又被租走的房源。

如果旧版已经因这个问题暂停，更新后点击面板的 **恢复并立即检查**，或使用菜单 **恢复故障暂停并立即检查**；无需清除历史。

## v1.3.11：故障暂停、持久化预算和接口等待

- **连续失败停止重试**：普通扫描失败第一次等至少 60 秒、第二次等至少 120 秒，第三次进入故障暂停，停止自动扫描和刷新，并尝试发送一次 Telegram 故障提醒。失败计数和等待时间保存到脚本存储，刷新页面不会清零。成功扫描后清零；处理页面问题后可用“恢复故障暂停并立即检查”或面板按钮恢复。
- **所有 Telegram 请求共用等待时间**：房源、验证、故障和测试提醒，以及配对请求，都经过同一发送队列并遵守持久化的等待截止时间。收到 Telegram 的 `retry_after` 时按要求等待，刷新页面后仍有效；发送失败时保留待发状态。
- **预算用菜单保存**：默认主租金上限仍为 €1000，使用“设置预算（主租金上限）”后保存在 Tampermonkey 中，不必再改源码。修改预算后重新完整扫描，保留原 Telegram 配置和成功通知记录。
- **被动观察接口异常**：脚本在页面开始加载时尝试观察页面的 `fetch` / XHR，不额外向 H2S 请求数据。观察范围限制为 `holland2stay.com` 和 `www.holland2stay.com` 下的 `/graphql`、`/rest`、`/api`、`/residences` 路径。发现 `cf-mitigated: challenge` 或 HTTP 403 时暂停，等待人工处理；HTTP 429 按 `Retry-After` 等待，至少等 60 秒。服务器 5xx 或网络错误进入等待并计入连续失败。等待结束后通过刷新获取新数据，避免将旧列表当作刚更新的房源。

接口验证/403 暂停保存在脚本存储中，不会被普通“立即检查”解除。在原浏览器完成处理后，使用“恢复接口暂停（验证完成后）”确认并刷新；普通故障恢复也不会跳过仍有效的接口限流等待。脚本不自动完成 Cloudflare 验证。

面板显示接口观察状态。**尚未核实官网实际房源接口地址**；浏览器、Tampermonkey 执行环境、响应头可读性及网站使用的请求方式都会影响覆盖，不能保证观察到每个请求。观察不可用或不完整时仍保留原有 DOM 验证检测与扫描完整性检查；这不是已在真实 H2S 验证通过的完整网络监控。

### 三个菜单有什么区别

| 菜单 | 行为 |
| --- | --- |
| 立即检查 | 扫描当前范围，按历史去重；没有新增或需再次通知的变化时不发消息 |
| 清除历史并重建基线（不通知现有房源） | 清除当前范围的房源记录；下次完整扫描把现有房源记住但不通知，之后新增、降价或重新可订等变化仍会通知 |
| 重新通知当前符合条件的房源（强制重发） | 下一次完整扫描后，把当前符合条件的房源再发一次，即使以前通知过；之后恢复去重 |

当前范围为所选目标城市；City 留空时是目标五城。两项历史操作均不清除 Telegram 配置。夜间设置后还需点“立即检查”，设置本身不立即扫描。

“扫描成功”不保证本轮有消息：“符合”统计符合房源总数，“本轮已发”统计本轮实际成功发送数。若只想检查消息通道，用“测试 Telegram”；若想再收到当前房源，用“强制重发”后“立即检查”，前提是有符合房源。脚本不额外发送每轮扫描完成消息。

这里修改的是网页浮窗。Tampermonkey 扩展弹出菜单的字体颜色由扩展界面决定，脚本的菜单注册接口不提供颜色选项。

## v1.3.8：采用用户在官网验证成功的 Price 触发方式

用户确认 Price 按钮可见、未禁用，鼠标点击有效，但反复执行 `button.click()` 没有效果。随后在官网控制台验证：给按钮焦点，以内部 `span` 为目标，带上文字区域中心坐标和 `detail: 1`，依次派发 `pointerdown → mousedown → pointerup → mouseup → click`，能够将排序标题切换成 `Price`。从 `Available start date` 和刷新后的 `Sort ...` 两种初始状态出发均成功。

v1.3.8 将这个已验证的完整组合用于 Price 选项。事件使用所属页面的 `PointerEvent` / `MouseEvent` 构造器；最后的 click 也使用 PointerEvent，与成功的控制台代码一致。展开 Sort 和翻页仍使用原有操作。

成功实验同时改变了目标节点、事件序列、焦点和事件参数，尚未单独确定官网依赖哪一个差异；不能据此声称官网必需 pointerdown 或只接受真实鼠标。派发事件后仍须读到官网 Price 标题或实际勾选项，才允许按预算扫描。加载等待、最多三次尝试和失败不更新历史的行为保留。

官网控制台实验已由用户验证，用户随后反馈 v1.3.8 的排序问题已解决。新增离线回归先在 v1.3.7 复现按钮点击无效，再验证内部文字事件、按下/松开、菜单关闭后的标题确认、异步排序及预算停止。该反馈不等于已验证实际 Telegram 投递。

## v1.3.7 历史修复：点击过 Price 后仍停在准备排序

“已点击 Price，但官网尚未显示 Price 选中”表示 `.click()` 已调用，但当前没有确认信号。v1.3.6 用 `clickedPrice` 布尔值将 Price 点击限制为一次，首次没有生效时会一直等到超时。这个停滞场景已用用户提供的 Available start date 标题及菜单结构复现；尚不能从状态面板确定用户页面首次点击未生效的具体原因。

现在每次重新读取可用按钮，在未加载、仍未确认 Price 时，间隔至少 3 秒、最多点击 3 次；`aria-busy=true` 期间等待，不重试。面板显示尝试次数和网页当前选中项。达到上限仍未确认则报错，不把点击次数当作排序成功，也不记录完整扫描。

排序控件和选中项统一排除 hidden / aria-hidden / display:none / visibility:hidden 的元素，防止隐藏旧菜单覆盖当前选项。隐藏旧 Date 误盖 Price、隐藏重复控件选错、首次点击未生效可恢复，以及加载中不重复点击都有离线回归覆盖。隐藏旧菜单只是修复的一个已复现代码缺陷，未证实用户当前页面存在此结构。

Console 中 `.click()` 返回 `undefined` 是正常返回值，不能凭此判断界面是否改变。请以网页按钮标题或菜单勾选项、脚本扫描状态判断。

## 当前规则

| 项目 | 行为 |
| --- | --- |
| 城市 | The Hague / Den Haag、Rijswijk、Rotterdam、Leiden、Zoetermeer |
| 预算 | 默认主租金 ≤ €1000，不含 servicekosten；可通过菜单保存新上限，等于上限包含 |
| 状态 | 只通知 Book directly / Available to book，排除 Lottery |
| Price | 按用户确认的站点规则视为从低到高；无需 Low to High 文字 |
| Available start date | 日期升序，不能用来按租金停止翻页 |
| 单页 | 完整读取并核对总数，无需排序 |
| 全站多页 | 选择并确认 Price，回到第一页，按预算停止翻页 |
| 单城多页 | Price 确认后按预算停止；无法确认时可完整读取当前城市 |
| 自动时间 | Europe/Amsterdam 07:00–23:00；夜间可手动扫描并通知 |
| 刷新 | 成功完成一轮后随机 5–15 分钟 |
| 等待 | 每页至少 10 秒并连续三次一致；单个等待阶段最多约 30 秒 |
| 操作 | 不自动切城市，不点击 Reset，遇到验证暂停 |
| 普通扫描失败 | 第 1 / 2 次至少等 60 / 120 秒，第 3 次故障暂停；刷新保留状态 |
| 接口异常 | 验证/403 人工恢复；429 遵守等待；临时错误等待并计入故障次数 |

已选 Price 会在当前页面内暂存确认，菜单收起不会丢失。实际已读价格仍检查页内及跨页顺序；重复 URL、总数变化、范围变化、未加载完整或顺序异常时不写入完成记录。没有通过这些检查的扫描不会视为无房源。

## 通知与历史

- **成功后去重**：详情 URL 作为房源 ID。只有 Telegram 返回成功才写入已通知记录；刷新页面、隔天运行、切换全站/单城模式或 Available to book 筛选都保留成功记录。
- **新增或变化**：首次发现、新房源、变为可直接预订、降价进入预算、预算内降价、连续两轮未在预算内列表出现后重新出现，会产生通知。
- **按城市更新**：只扫描 The Hague 时，不会把没有检查的 Leiden 房源当成消失。全站模式会更新五城的预算内记录。
- **完整性校验**：从第 1 页开始，出现重复 URL、城市不符、页码错误、总数变化或加载不完整时，放弃本轮历史更新。选定 Available to book 后，列表还残留抽签/不可订卡片时等待页面完成切换。完整读取模式核对全部卡片数量等于官网总数。
- **排序校验与减少分页**：按用户指定的站点规则将 Price 视为升序，并启用预算截断，并检查已读页面内、页面间的主租金顺序；价格倒序会中止本轮。升序确认后，读到超预算房源就结束；如果一直没有超预算房源，则必须读到末页并核对总数。Available start date 不用于租金预算截断。这里只采用用户指定的排序规则，没有通过后端代码独立验证全站排序含义。
- **发送与翻页分开**：同一范围内的手动翻页不会打断已经确认房源的发送。切换城市/筛选、手动暂停或出现验证时会停发，未发送的记录保留。
- **发送重试**：Telegram 网络错误或限流时，保留待发并按至少 60 秒或服务器指定时间等待。所有 Telegram 请求共用等待截止时间，刷新页面后仍保留。同一页面中，刚完成扫描的通知可直接续发，无需重扫 H2S。夜间手动检查产生的队列也能续发；15 分钟后不再使用旧扫描结果，等待下一次扫描重新确认。刷新/关闭页面后，下一次扫描会读取保留的待发记录。
- **夜间**：23:00–07:00 不自动启动新扫描；“立即检查”可以扫描并通知。没有需要通知的房源时，不额外发送扫描完成消息。
- **验证暂停**：识别实际验证页或访问受阻提示后停止刷新，尝试通知你手动处理。同一事件只成功提醒一次；不会自动点击验证控件。被接口观察识别出的验证/403 需要使用专用恢复菜单确认处理完成。
- **扫描故障暂停**：连续普通扫描失败按 60 秒、120 秒递增等待，第三次暂停并尝试发送故障提醒。同一故障暂停成功提醒一次，失败时按共享 Telegram 等待时间重试；刷新不会重置失败次数。
- **一个监控标签页**：同一网站源、同一配置使用 Web Locks，只允许一个标签页执行监控。

Telegram 响应丢失时，服务器可能已收到消息但脚本无法确认，重试仍可能产生重复。列表在两个扫描之间短暂出现又消失的房源也可能无法观察到。

## Telegram 配置与菜单

Token 和 Chat ID 都保存在 Tampermonkey 的脚本存储中，代码不包含你的凭据。

1. 在 Telegram 官方 [@BotFather](https://t.me/BotFather) 创建机器人，取得 Token。
2. 私聊自己的机器人，点 Start 或发送 `/start`。
3. 在 H2S 页打开 Tampermonkey 菜单，选择“配置 Telegram Token”。
4. 选择“自动获取 Chat ID（配对）”，把弹窗中的 `h2s-...` 文字发给机器人，再确认。也可选择“手动配置 Chat ID”。
5. 点击“测试 Telegram”，确认收到测试消息。

| 菜单 | 作用 |
| --- | --- |
| 立即检查 | 检查当前范围，夜间也可以；解除普通故障计数，但不跳过接口暂停或限流；手动暂停时需先恢复 |
| 设置预算（主租金上限） | 保存每月主租金上限，更新脚本后保留；下一次完整扫描按新预算判断 |
| 恢复故障暂停并立即检查 | 处理普通扫描问题后重新检查；不能解除接口暂停或限流 |
| 恢复接口暂停（验证完成后） | 人工处理接口验证/403 后确认并刷新页面；不会自动完成验证 |
| 暂停 / 恢复 | 暂停或恢复扫描及房源通知 |
| 清除历史并重建基线（不通知现有房源） | 清除当前范围的房源记录，跳过下次预算内扫描的已有房源通知；其他城市保留 |
| 重新通知当前符合条件的房源（强制重发） | 下次完成当前范围扫描后重发符合条件的房源；后续继续去重 |
| 查看历史 | 查看最多 100 条最近记录的房源及待发标记 |
| 测试 Telegram | 仅验证消息发送配置 |
| 测试 Cloudflare 提醒 | 仅发送提醒测试消息，不会触发网站验证 |

正常扫描不需要点清除或重发。夜间设置了静默重建或强制重发后，再点“立即检查”执行。

const TARGET_CITIES = ['The Hague', 'Rijswijk', 'Rotterdam', 'Leiden', 'Zoetermeer'];

预算请使用“设置预算（主租金上限）”，已保存的设置优先于 `DEFAULT_MAX_RENT`。预算判断只使用主租金，脚本不会判断房补、收入或学生资格。修改预算后会重新计算资格并保留成功通知记录。`STORAGE_PREFIX` 通常不改；新前缀代表另一套 Telegram 配置和历史。

普通安装不需要 Node.js。维护代码使用 Node.js 20+：

```bash
npm ci
npm test
npm run check
```

`linkedom` 只用于离线测试；Tampermonkey 脚本不加载外部库，也不直接调用 H2S API；它只尝试被动观察网页自己的相关请求。原始整页 HTML、账户配置和通知历史不提交仓库。
