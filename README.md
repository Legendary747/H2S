# H2S 五城市房源监控

在你自己的浏览器中用 Tampermonkey 读取 Holland2Stay 的**全部城市房源列表**，再由脚本在本地筛选 The Hague、Rijswijk、Rotterdam、Leiden、Zoetermeer，通过 Telegram 提醒。GitHub 用于管理代码；安装脚本、保持电脑联网且不休眠、打开 H2S 列表页后，监控才会运行。

**不需要在官网勾选这五个城市，也不需要打开五个标签页。** H2S 的城市选项会随当前房源变化，而且选择城市可能立即刷新页面，因此脚本完全不依赖城市选项是否存在。某城暂时没有房源，之后新房出现时仍能被识别。

## 当前默认设置

| 设置 | 默认值 |
| --- | --- |
| 通知城市 | The Hague / Den Haag、Rijswijk、Rotterdam、Leiden、Zoetermeer |
| 数据来源 | 无网页筛选的全部城市列表，完整扫描所有分页 |
| 网页已有筛选 | 默认尝试点击官网 Reset 清除；未清除成功则不更新历史 |
| 主租金上限 | €1,000 / 月，不含 servicekosten 等额外费用 |
| 房源状态 | Book directly / Available to book |
| 自动运行时段 | Europe/Amsterdam 每天 07:00–23:00，自动适配夏令时 |
| 完整刷新间隔 | 一轮扫描完成后随机 5–15 分钟 |
| 初次运行 | 建立完整基线，默认不通知现有房源 |
| 通知事件 | 新房源、变为可直接预订、主租金下降、重新出现 |
| 验证页面 | 停止刷新，提醒手动处理；恢复后重新扫描 |

## 安装和启动

1. 给常用的 Chrome、Edge 或 Firefox 安装 [Tampermonkey](https://www.tampermonkey.net/)。按扩展提示启用用户脚本权限，并允许它访问 H2S。
2. 在本仓库打开 [`h2s-monitor.user.js`](h2s-monitor.user.js)，复制**完整文件**。在 Tampermonkey 中新建脚本，删除默认模板，粘贴并保存。私有仓库用这种方式安装即可，不需要把仓库设为公开，也不需要把 GitHub 凭据写进脚本。
3. 打开 <https://www.holland2stay.com/residences>，使用官网的英文界面。如果出现验证，请先手动完成。
4. **保留全部城市，不勾选 City 或其他网页筛选。** 如果之前已选城市，脚本会尝试点击官网 **Reset**。无法自动清除时，状态框会提示你手动清除；它不会把某个城市的局部结果当成完整列表。
5. 保持这个标签页打开。右下角状态框会显示扫描数量、符合条件的数量、通知数量、Telegram 状态及下次刷新时间。

从旧版更新时，在 **Tampermonkey 里编辑原来的脚本**，全选替换代码并保存，然后刷新 H2S。原来的脚本名称与存储前缀特意保留，方便继续使用已保存的 Telegram 配置；右下角会显示五城市范围。不要同时启用旧版和新版。更新后的第一次完整扫描会重建基线。

晚上 23:00 后自动监控暂停。想在夜间检查安装是否正常，可以在 Tampermonkey 菜单点击 **立即检查（允许在夜间手动执行）**。手动检查同样遵守完整列表要求、暂停状态和验证暂停逻辑。

首次完整扫描显示“已建立完整基线”后，后续出现的符合条件房源才会通知。若要查看当前已有的符合条件房源，可以使用“清除通知历史并重新通知当前符合条件的房源”，然后“立即检查”。该操作会先请你确认。

## 配置 Telegram

Token 和 Chat ID 都保存在 Tampermonkey 的脚本存储中，代码里没有预置凭据。

1. 在 Telegram 官方 [@BotFather](https://t.me/BotFather) 创建一个专用机器人，取得 Token。
2. 私聊你创建的机器人，点 **Start** 或发送 `/start`。
3. 在 H2S 页打开 Tampermonkey 菜单，选择 **配置 Telegram Token** 并填写。
4. 选择 **自动获取 Chat ID（配对）**。把弹窗给出的 `h2s-...` 文字发送到你与机器人的私聊中，发送后回到弹窗点确定。脚本只接受包含本次配对文字的唯一私聊，避免把消息发给其他聊天。
5. 点击 **测试 Telegram**，确认你收到了测试消息。

也可以使用“手动配置 Chat ID”。如果该机器人已被其他程序设置为 webhook，自动配对可能失败；脚本不会更改它的 webhook，届时可以手动填写 Chat ID 或使用专用机器人。

菜单中的测试消息只验证发送配置。通知功能真正运行还需要状态框显示已完成房源扫描。

## 扫描和通知规则

- **完整分页**：通过网页上的页码/Next page 控件逐页浏览，不直接调用 H2S API。每页至少观察 10 秒，连续三次内容一致后才读取；单次等待最多 30 秒。只有所有页解析成功、URL 无重复、房源数量与页面总数一致，才更新历史。完整扫描最多 50 页，超出会明确报错。
- **本地五城市筛选**：先读取完整的全城市列表，再按 `TARGET_CITIES`、主租金和可订状态筛选。其他城市的卡片不会触发通知。城市选项出现、消失或数量变化不改变基线，也不会关闭对应城市的监控。修改脚本里的目标城市或预算后才重新建立基线。
- **监控页不保留网页筛选**：脚本核实 `Current Filters` 区域为空且已呈现的筛选项没有被勾选。如有筛选，默认尝试一次官网 Reset 并确认清空；失败会说明原因，避免重复点击造成刷新循环。要人工筛选浏览房源，先暂停脚本。该脚本不会自动判断房补资格、收入要求或学生资格。
- **租金识别**：读取实际页面的主租金区域，要求金额紧邻 `per month excl.*` 标签。`servicekosten ... amount to €... per month` 不作为主租金。格式异常时停止本轮，不猜金额。
- **动态内容**：等待期间持续观察页面，并在空闲时监听 DOM 变化。加载失败或卡片尚未出现不等于零房源。网页改版导致字段无法确认时，状态框会说明原因。
- **去重与状态变化**：规范化详情 URL 作为 ID，保存租金、状态和通知记录。相同状态不重复提醒。连续两次完整扫描都没出现的房源，之后重新出现且符合条件时，会再次提醒；一轮短暂缺失不会立即触发重新出现提醒。
- **可靠重试**：仅在 Telegram 返回成功后记录“已通知”。失败则保留待发状态，在之后扫描时重试；不再符合条件或已消失的房源会取消待发。极端情况下，服务器收到消息但响应丢失，重试可能产生重复消息，无法承诺端到端恰好一次。
- **验证暂停**：识别实际验证页/访问受阻提示，不因为普通页面包含 Cloudflare 或 Turnstile 组件就暂停。同一事件只成功通知一次；约每 5 秒检查页面是否恢复，不点击验证控件、不自动刷新验证页。正常页面恢复后继续运行。
- **多个标签页**：同一网站源、同一配置通过 Web Locks 只允许一个标签页监控，其他标签页等待。五个城市共用一个监控标签页即可，避免同时在不同浏览器或不同配置副本中运行。

网页提供的房源总数也可能在翻页期间变化，脚本会放弃不一致的扫描并稍后重试。你上传的页面有 11 页，按每页至少等待 10 秒，一轮完整扫描至少约 110 秒，之后再等待 5–15 分钟刷新。轮询和翻页不是即时推送；两个扫描间短暂出现又消失的房源可能看不到。后台标签页的计时也可能被浏览器延迟。

## 修改城市、预算或时段

脚本顶部可以修改：

```javascript
const TARGET_CITIES = ['The Hague', 'Rijswijk', 'Rotterdam', 'Leiden', 'Zoetermeer'];
const MAX_RENT = 1000;
const AUTO_RESET_FILTERS = true;
const STORAGE_PREFIX = 'h2s_single_city_den_haag';
const TIME_ZONE = 'Europe/Amsterdam';
const START_HOUR = 7;
const END_HOUR = 23;
```

添加或删除城市只需修改 `TARGET_CITIES`，无需在官网选择城市。设置 `AUTO_RESET_FILTERS = false` 可以关闭自动清除网页筛选，此时你需手动保持全部城市列表。`STORAGE_PREFIX` 用来隔离历史、暂停状态和 Telegram 配置，通常无需修改；新前缀需要重新配置 Telegram。

## 已验证内容与剩余验证

实现基于用户上传的 2026-10-03 房源列表 HTML。该页面显示总计 **109** 套，当前 DOM 中有 **10** 张卡片，分页共 **11** 页。测试样本保留这些公开房源节点，移除了网页脚本、图片、登录表单和其他无关内容，未提交原始整页文件。

离线测试确认：

- 10 套房源主租金全部正确提取。
- `Kasteellaan 73, The Hague` 主租金为 **€1,778.00**，不会误用 **€67.50** 的附加费用；因此它不符合本脚本 €1,000 的预算上限。这不表示官网其他页面没有符合条件的房源。
- 实际分页控件在模拟动态页面中能完成多页扫描并从最后一页返回第一页。
- 不完整加载、未清除的网页筛选、验证页面不会建立错误基线。
- 城市选项中没有 The Hague 时仍能完成扫描；之后 The Hague 新房源出现，会产生新房通知而不是重建基线。
- 全城市列表中的无关城市会被忽略；指定五城、预算和直接可订状态同时用于筛选。
- 通知失败重试、降价、重新可订、重新出现和荷兰时区行为正确。

19 项离线测试和 JavaScript 语法检查已通过。尚未验证：你浏览器里的实时 H2S Reset/翻页、长时间后台运行，以及真实 Telegram 发送。安装后用“立即检查”和“测试 Telegram”完成实际检查。原始样本中的 City 选项是折叠的，这不影响新版运行；新版不需要展开或读取城市选项。
