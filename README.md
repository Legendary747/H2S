# H2S 五城市房源监控

Tampermonkey 脚本 **v1.3.0**：在你自己的浏览器中读取 Holland2Stay 房源列表，使用 **Price: low to high（价格从低到高）** 排序，遇到主租金超过预算的房源后停止翻下一页。满足城市、主租金、可订状态的房源通过 Telegram 通知。

GitHub 用于保存代码。监控需要电脑联网、不休眠，并保持浏览器的 H2S 列表页打开。

## 两种扫描范围

| 网页上的选择 | 脚本行为 |
| --- | --- |
| 没有选择城市，也没有其他网页筛选 | 在主页按价格升序读取，只通知 The Hague / Den Haag、Rijswijk、Rotterdam、Leiden、Zoetermeer |
| 手动选择了上述五城之一 | 只读取这个城市的预算内房源和分页 |
| 选择了其他城市 | 显示该城市不在目标范围，不开始扫描 |
| 同时选了多个城市，或叠加其他网页筛选 | 提示只保留一个 City 或清除筛选，不开始扫描 |

脚本不会点击 Reset，也不会自动切换城市。官网某个城市选项暂时消失时，可以使用没有城市筛选的主页模式，继续关注该城以后出现的房源。

## 当前默认设置

| 设置 | 默认值 |
| --- | --- |
| 目标城市 | The Hague / Den Haag、Rijswijk、Rotterdam、Leiden、Zoetermeer |
| 主租金上限 | **€1,500 / 月**，沿用用户当前设置；不包含 servicekosten 等额外费用 |
| 房源状态 | Book directly / Available to book；抽签房源不通知 |
| 排序 | Price: low to high；脚本尝试选择，并核实升序状态 |
| 停止翻页 | 已读取页面出现主租金 **> €1,500** 的房源；€1,500 本身仍包含在预算内 |
| 自动运行 | Europe/Amsterdam 每天 07:00–23:00，自动适配冬夏令时 |
| 刷新间隔 | 一轮扫描结束后随机 5–15 分钟 |
| 页面稳定等待 | 每页至少 10 秒，连续三次读取一致；最多等待约 30 秒 |
| 分页上限 | 最多 50 页；预算内尚未读完时不会更新历史 |
| 首次通知 | 第一次完成预算内扫描就通知当前符合条件的房源 |

脚本读取当前页的全部卡片并检查价格顺序，因此会读到第一次出现超预算房源的那一页。如果这一页同时有预算内和超预算的房源，会处理其中符合条件的房源，然后停止继续翻页。

读取 DOM 本身不会额外请求 H2S。网页排序、翻页、定时刷新仍会加载官网数据；提前停止减少的是超出预算部分的翻页请求。

## 安装或更新

1. 安装 [Tampermonkey](https://www.tampermonkey.net/)，按扩展提示启用脚本权限并允许访问 H2S。
2. 打开本仓库的 [`h2s-monitor.user.js`](h2s-monitor.user.js)，复制完整内容。新安装时新建脚本并替换默认模板；更新时在 **Tampermonkey 里编辑原来的脚本**，全选替换、保存。
3. 刷新 <https://www.holland2stay.com/residences>，使用官网英文界面。出现验证时先手动完成。
4. 使用没有网页筛选的主页，或者手动选择目标五城中的一个城市。
5. 确认右下角显示当前范围、允许扫描、价格升序和扫描状态。
6. 夜间点击菜单 **立即检查（允许在夜间手动执行）**。

脚本名称和存储前缀继续保留，方便沿用 Telegram 配置。v1.0–v1.2 的成功通知和待发记录会自动按城市迁移；更新不会把已成功通知的相同房源全部重新推送。不要同时启用旧版和新版。

若提示“未能确认升序排序”，请在官网 Sort 中手动选择 **Price: low to high**，然后点击“立即检查”。确认不了排序时，脚本会停止并提示，不会在未知顺序下按预算截断。

## 状态框如何阅读

| 显示项 | 含义 |
| --- | --- |
| 当前城市 | 你选中的城市，或“全部城市（本地筛选五城）” |
| 目标城市 | 当前城市是否属于允许的五城；主页模式显示五城范围 |
| 允许扫描 | 是否满足城市及网页筛选要求；不允许时显示原因 |
| 价格排序 | 是否确认从低到高 |
| 扫描状态 | 未开始、准备排序、等待列表稳定、扫描中、扫描已完成、通知发送中、通知等待重试、夜间暂停等 |
| 已读 / 符合 / 第几页 | 当前范围读取的卡片数量、符合城市/主租金/直接可订条件的数量及页码 |
| 本轮已发 | 本轮 Telegram 已确认成功的通知数 |
| 当前范围待发 | 当前范围仍等待发送的通知数；夜间暂停后也保留显示 |
| 累计 | 已成功通知的累计次数，包括旧版记录 |
| 其他城市 / 范围待复查 | 保存了待发记录，但本次没有覆盖或不满足当前预算；需要对应范围的新扫描确认 |
| Telegram | 配置情况、实际发送成功或 Telegram 请求错误；手动操作暂停不会显示成 Telegram 错误 |
| 上次扫描终点 | 因超过预算停止翻页，或已经读到最后一页 |

“符合 31 套”不等于“本轮必须新发 31 条”：其中可能有已经通知过的房源。发送中途停止时，剩余通知保存在待发队列。旧版把翻页等手动操作的等待逻辑也套在通知发送上，可能导致发送了 6 条后停止；新版把这两部分分开。

## 通知与历史

- **成功后去重**：详情 URL 作为房源 ID。只有 Telegram 返回成功才写入已通知记录；刷新页面、隔天运行、切换全站/单城模式都保留成功记录。
- **新增或变化**：首次发现、新房源、变为可直接预订、降价进入预算、预算内降价、连续两轮未在预算内列表出现后重新出现，会产生通知。
- **按城市更新**：只扫描 The Hague 时，不会把没有检查的 Leiden 房源当成消失。全站模式会更新五城的预算内记录。
- **排序校验**：确认官网升序选项，并检查已读页面内部及页面之间的主租金顺序。从第 1 页开始，出现重复 URL、城市不符、页码错误、总数变化、加载不完整或价格倒序时，放弃本轮历史更新。
- **减少分页**：升序确认后，读到超预算房源就结束；如果一直没有超预算房源，则必须读到末页并核对总数。
- **发送与翻页分开**：同一范围内的手动翻页不会打断已经确认房源的发送。切换城市/筛选、手动暂停或出现验证时会停发，未发送的记录保留。
- **发送重试**：Telegram 网络错误或限流时，保留待发并按至少 60 秒或服务器指定时间等待。同一页面中，刚完成扫描的通知可直接续发，无需重扫 H2S。夜间手动检查产生的队列也能续发；15 分钟后不再使用旧扫描结果，等待下一次扫描重新确认。刷新/关闭页面后，下一次扫描会读取保留的待发记录。
- **夜间**：23:00–07:00 不自动启动新扫描；“立即检查”可以扫描并通知。没有需要通知的房源时，不额外发送扫描完成消息。
- **验证暂停**：识别实际验证页或访问受阻提示后停止刷新，尝试通知你手动处理。同一事件只成功提醒一次；不会自动点击验证控件。
- **一个监控标签页**：同一网站源、同一配置使用 Web Locks，只允许一个标签页执行监控。

Telegram 响应丢失时，服务器可能已收到消息但脚本无法确认，重试仍可能产生重复。列表在两个扫描之间短暂出现又消失的房源也可能无法观察到。

## Telegram 配置与菜单

Token 和 Chat ID 都保存在 Tampermonkey 的脚本存储中，代码不包含你的凭据。

1. 在 Telegram 官方 [@BotFather](https://t.me/BotFather) 创建机器人，取得 Token。
2. 私聊自己的机器人，点 Start 或发送 `/start`。
3. 在 H2S 页打开 Tampermonkey 菜单，选择“配置 Telegram Token”。
4. 选择“自动获取 Chat ID（配对）”，把弹窗中的 `h2s-...` 文字发给机器人，再确认。也可选择“手动配置 Chat ID”。
5. 点击“测试 Telegram”，确认收到测试消息。

| 菜单 | 作用 |
| --- | --- |
| 立即检查 | 检查当前范围，夜间也可以；手动暂停时需先恢复 |
| 暂停 / 恢复 | 暂停或恢复扫描及房源通知 |
| 清除历史并重建基线（不通知现有房源） | 清除当前范围的房源记录，跳过下次预算内扫描的已有房源通知；其他城市保留 |
| 重新通知当前符合条件的房源（强制重发） | 下次完成当前范围扫描后重发符合条件的房源；后续继续去重 |
| 查看历史 | 查看最多 100 条最近记录的房源及待发标记 |
| 测试 Telegram | 仅验证消息发送配置 |
| 测试 Cloudflare 提醒 | 仅发送提醒测试消息，不会触发网站验证 |

正常扫描不需要点清除或重发。夜间设置了静默重建或强制重发后，再点“立即检查”执行。

## 修改参数

```javascript
const TARGET_CITIES = ['The Hague', 'Rijswijk', 'Rotterdam', 'Leiden', 'Zoetermeer'];
const MAX_RENT = 1500;
const STORAGE_PREFIX = 'h2s_single_city_den_haag';
const TIME_ZONE = 'Europe/Amsterdam';
const START_HOUR = 7;
const END_HOUR = 23;
const REFRESH_MINUTES = [5, 15];
const MIN_SETTLE_MS = 10000;
const MAX_SETTLE_MS = 30000;
const MAX_PAGES = 50;
```

预算判断只使用主租金，脚本不会判断房补、收入或学生资格。修改预算后会重新计算资格并保留成功通知记录。`STORAGE_PREFIX` 通常不改；新前缀代表另一套 Telegram 配置和历史。

## 验证与开发

**33 项离线测试和 JavaScript 语法检查通过。** 测试覆盖真实 HTML 中的主租金提取、五城识别、价格排序及预算边界、提前停止翻页、价格倒序保护、单城/全站切换、旧历史迁移、发送 6 条后的 25 条重试、夜间手动通知及去重。Telegram 请求全部由测试模拟，没有发送真实消息。

原始上传 HTML 中 Sort 控件处于收起状态，City 选项也未展开；已有控件容器与卡片结构来自该样本，展开后的排序选项和城市筛选由测试场景模拟。真实浏览器中点击排序、选择城市、后台长时间运行和 Telegram 发送仍需实际安装验证。原始整页中的脚本、登录表单和其他无关内容没有提交到仓库。

普通安装不需要 Node.js。维护代码时使用 Node.js 20+：

```bash
npm ci
npm test
npm run check
```

`linkedom` 只用于离线测试；Tampermonkey 脚本不加载外部库，也不直接调用 H2S API。
