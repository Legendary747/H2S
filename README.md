# H2S 五城市房源监控

Tampermonkey 脚本 **v1.3.4**：在你自己的浏览器中读取 Holland2Stay 房源列表。只有一页时直接读完，无需排序；有多页时尝试官网 **Price** 排序。只有明确确认主租金升序时才在超预算后停止翻页；无法确认方向时，完整读取你手动选择的一个目标城市。满足城市、主租金、可订状态的房源通过 Telegram 通知。允许保留 **Available to book** 网页筛选。

GitHub 用于保存代码。监控需要电脑联网、不休眠，并保持浏览器的 H2S 列表页打开。

## 两种扫描范围

| 网页上的选择 | 脚本行为 |
| --- | --- |
| 没有选择城市，或只选择 Available to book | 单页直接读完；多页须确认升序才开始预算截断扫描，否则提示先选一个目标城市。只通知 The Hague / Den Haag、Rijswijk、Rotterdam、Leiden、Zoetermeer |
| 手动选择了上述五城之一，可同时选 Available to book | 单页无需排序；多页确认升序时在超预算后停止，否则读完该城市全部页，再筛选预算内房源 |
| 选择了其他城市 | 显示该城市不在目标范围，不开始扫描 |
| 同时选了多个城市，选择其他 Availability 状态，或叠加其他网页筛选 | 显示对应类别的问题；允许保留一个目标 City 和 Available to book，其余筛选需清除 |

脚本不会点击 Reset，也不会自动切换城市。官网城市选项由当前房源生成；选定一个城市只会监控这个城市。主页模式只有单页或可确认升序时才能覆盖五城，不会在未知排序下重新遍历全站。

你上传的截图中，官网菜单只有 **Available start date / Price**，没有 **Price: low to high**。新版能够识别 Price，但不会把这个没有方向的文字当作全局主租金升序保证。当前建议手动选定一个目标城市，再运行脚本。

## 当前默认设置

| 设置 | 默认值 |
| --- | --- |
| 目标城市 | The Hague / Den Haag、Rijswijk、Rotterdam、Leiden、Zoetermeer |
| 主租金上限 | **€1,500 / 月**，沿用用户当前设置；不包含 servicekosten 等额外费用 |
| 房源状态 | Book directly / Available to book；抽签房源不通知 |
| 排序 | 单页不操作 Sort；多页识别或尝试选择 Price，并区分“已选择价格排序”和“明确升序” |
| 停止翻页 | 明确升序时，已读取页面出现主租金 **> €1,500** 即停止；方向未知时只读完当前所选城市。€1,500 本身仍包含在预算内 |
| 自动运行 | Europe/Amsterdam 每天 07:00–23:00，自动适配冬夏令时 |
| 刷新间隔 | 一轮扫描结束后随机 5–15 分钟 |
| 页面稳定等待 | 每页至少 10 秒，连续三次读取一致；最多等待约 30 秒 |
| 分页上限 | 最多 50 页；预算内尚未读完时不会更新历史 |
| 首次通知 | 第一次完成预算内扫描就通知当前符合条件的房源 |

在确认升序的预算截断模式下，脚本读取当前页的全部卡片并检查价格顺序，因此会读到第一次出现超预算房源的那一页。如果这一页同时有预算内和超预算的房源，会处理其中符合条件的房源，然后停止继续翻页。单页或城市完整读取模式不要求价格顺序，必须核对全部卡片的唯一数量等于官网总数，才会更新历史和开始通知。

读取 DOM 本身不会额外请求 H2S。网页排序、翻页、定时刷新仍会加载官网数据；提前停止减少的是超出预算部分的翻页请求。

## 安装或更新

1. 安装 [Tampermonkey](https://www.tampermonkey.net/)，按扩展提示启用脚本权限并允许访问 H2S。
2. 打开本仓库的 [`h2s-monitor.user.js`](h2s-monitor.user.js)，复制完整内容。新安装时新建脚本并替换默认模板；更新时在 **Tampermonkey 里编辑原来的脚本**，全选替换、保存。
3. 刷新 <https://www.holland2stay.com/residences>，使用官网英文界面。出现验证时先手动完成。
4. 手动选择目标五城中的一个城市，可同时保留 Available to book；主页模式需要满足上表的排序条件。
5. 确认右下角显示当前范围、允许扫描、排序和扫描状态。单页会显示“当前仅一页，无需排序”。
6. 夜间点击菜单 **立即检查（允许在夜间手动执行）**。不必先手动排序；单页直接读完，多页尝试 Price，无法确认升序则读完当前选定城市。

脚本名称和存储前缀继续保留，方便沿用 Telegram 配置。v1.0–v1.2 的成功通知和待发记录会自动按城市迁移；更新不会把已成功通知的相同房源全部重新推送。不要同时启用旧版和新版。

v1.3.1 修复了“只选 The Hague 却提示有其他筛选”的误判：官网把 **Clear all filters** 操作按钮放在已选筛选列表里，现在会单独排除这个按钮，真正的其他筛选仍会被识别。刚手动选择城市或排序就点“立即检查”时，脚本会显示剩余等待秒数，等 30 秒操作观察期结束后自动继续；无需再次点击。

v1.3.2 修复了卡在“正在选择 Price: low to high”的问题：旧版只接受网站实际没有显示的完整文字。现在识别官网 Price，已经选中时不会反复打开菜单。单页扫描不依赖 Sort 控件，即使页面未排序、倒序或没有 Sort 也能完整核对。你上传的 The Hague 页面包含 9 套，其中 3 套满足主租金 ≤ €1,500 且 Book directly；另外的抽签和超预算房源不会通知。是否产生新通知仍取决于已有成功记录。

v1.3.3 根据你提供的真实展开菜单修复了后续问题：官网选项是 `li > button > span`，之前可能点击外层 li，未触发内部按钮的点击事件。现在优先点击 `SortItem-button` / `SortItem-activeButton` 按钮，并读取 `SortItem-activeButton` 确认实际选项；即使标题仍显示 Sort ... 也能识别。菜单已打开时不重复开关，Price 已选中时不重复选择。真实选中项优先于可能尚未更新的标题文字。

v1.3.4 修复了把 Available to book 当成城市的问题：删除“未识别到 City 就把所有标签当城市”的兜底逻辑，按 City、Availability 和其他筛选分别识别。只有 City 控件、明确 City 标签或已知城市名称才提供城市依据；不认识的标签会报告为未支持的筛选。只选 Available to book 显示“当前城市：全部城市”，与 The Hague 同时选择则显示“The Hague”；可订状态独立显示。Available in lottery、Occupied、装修和租金等标签不会再被当成城市。切换 Availability 会取消尚未完成的扫描，重新核对范围；已成功通知的记录继续保留。

主页有多页却只能识别到 Price 时，会提示“请手动选择一个目标城市后立即检查”。这是为了避免排序方向不明确时漏掉后面的便宜房源，同时避免遍历全站。

## 状态框如何阅读

| 显示项 | 含义 |
| --- | --- |
| 当前城市 | 你选中的城市，或“全部城市（本地筛选五城）” |
| 可订状态 | Available to book，或“未筛选（仅通知可直接预订）”；与城市分开显示 |
| 目标城市 | 当前城市是否属于允许的五城；主页模式显示五城范围 |
| 允许扫描 | 是否满足城市及网页筛选要求；不允许时显示原因 |
| 价格排序 | 单页无需排序、已选择 Price 但方向未确认，或已确认从低到高 |
| 扫描方式 | 未确认升序的单城多页扫描会注明“读完当前城市全部页，再按预算筛选” |
| 扫描状态 | 未开始、准备排序、等待列表稳定、扫描中、扫描已完成、通知发送中、通知等待重试、夜间暂停等 |
| 已读 / 符合 / 第几页 | 当前范围读取的卡片数量、符合城市/主租金/直接可订条件的数量及页码 |
| 本轮已发 | 本轮 Telegram 已确认成功的通知数 |
| 当前范围待发 | 当前范围仍等待发送的通知数；夜间暂停后也保留显示 |
| 累计 | 已成功通知的累计次数，包括旧版记录 |
| 其他城市 / 范围待复查 | 保存了待发记录，但本次没有覆盖或不满足当前预算；需要对应范围的新扫描确认 |
| Telegram | 配置情况、实际发送成功或 Telegram 请求错误；手动操作暂停不会显示成 Telegram 错误 |
| 上次扫描终点 | 因超过预算停止翻页，或已经读到最后一页 |

“符合 31 套”不等于“本轮必须新发 31 条”：其中可能有已经通知过的房源。发送中途停止时，剩余通知保存在待发队列。旧版把翻页等手动操作的等待逻辑也套在通知发送上，可能导致发送了 6 条后停止；新版把这两部分分开。

## 通知与历史

- **成功后去重**：详情 URL 作为房源 ID。只有 Telegram 返回成功才写入已通知记录；刷新页面、隔天运行、切换全站/单城模式或 Available to book 筛选都保留成功记录。
- **新增或变化**：首次发现、新房源、变为可直接预订、降价进入预算、预算内降价、连续两轮未在预算内列表出现后重新出现，会产生通知。
- **按城市更新**：只扫描 The Hague 时，不会把没有检查的 Leiden 房源当成消失。全站模式会更新五城的预算内记录。
- **完整性校验**：从第 1 页开始，出现重复 URL、城市不符、页码错误、总数变化或加载不完整时，放弃本轮历史更新。选定 Available to book 后，列表还残留抽签/不可订卡片时等待页面完成切换。完整读取模式核对全部卡片数量等于官网总数。
- **排序校验与减少分页**：只在官网明确标出升序时启用预算截断，并检查已读页面内、页面间的主租金顺序；价格倒序会中止本轮。升序确认后，读到超预算房源就结束；如果一直没有超预算房源，则必须读到末页并核对总数。只有 Price 文字时不能据此证明全局主租金升序，单城改用完整读取。
- **发送与翻页分开**：同一范围内的手动翻页不会打断已经确认房源的发送。切换城市/筛选、手动暂停或出现验证时会停发，未发送的记录保留。
- **发送重试**：Telegram 网络错误或限流时，保留待发并按至少 60 秒或服务器指定时间等待。同一页面中，刚完成扫描的通知可直接续发，无需重扫 H2S。夜间手动检查产生的队列也能续发；15 分钟后不再使用旧扫描结果，等待下一次扫描重新确认。刷新/关闭页面后，下一次扫描会读取保留的待发记录。
- **夜间**：23:00–07:00 不自动启动新扫描；“立即检查”可以扫描并通知。没有需要通知的房源时，不额外发送扫描完成消息。
- **验证暂停**：识别实际验证页或访问受阻提示后停止刷新，尝试通知你手动处理。同一事件只成功提醒一次；不会自动点击验证控件。
- **一个监控标签页**：同一网站源、同一配置使用 Web Locks，只允许一个标签页执行监控。

Telegram 响应丢失时，服务器可能已收到消息但脚本无法确认，重试仍可能产生重复。列表在两个扫描之间短暂出现又消失的房源也可能无法观察到。

## Telegram 配置与菜单

Token 和 Chat ID 都保存在 Tampermonkey 的脚本存储中，代码不包含你的凭据。

1. 在 Telegram 官方 [@BotFather](https://t.me/BotFather) 创建机器人，取得 Token。
2. 私聊自己的机器人，点 Start 或发送 `/start`。
3. 在 H2S 页打开 Tampermonkey 菜单，选择“配置 Telegram Token”。
4. 选择“自动获取 Chat ID（配对）”，把弹窗中的 `h2s-...` 文字发给机器人，再确认。也可选择“手动配置 Chat ID”。
5. 点击“测试 Telegram”，确认收到测试消息。

| 菜单 | 作用 |
| --- | --- |
| 立即检查 | 检查当前范围，夜间也可以；手动暂停时需先恢复 |
| 暂停 / 恢复 | 暂停或恢复扫描及房源通知 |
| 清除历史并重建基线（不通知现有房源） | 清除当前范围的房源记录，跳过下次预算内扫描的已有房源通知；其他城市保留 |
| 重新通知当前符合条件的房源（强制重发） | 下次完成当前范围扫描后重发符合条件的房源；后续继续去重 |
| 查看历史 | 查看最多 100 条最近记录的房源及待发标记 |
| 测试 Telegram | 仅验证消息发送配置 |
| 测试 Cloudflare 提醒 | 仅发送提醒测试消息，不会触发网站验证 |

正常扫描不需要点清除或重发。夜间设置了静默重建或强制重发后，再点“立即检查”执行。

```javascript
const TARGET_CITIES = ['The Hague', 'Rijswijk', 'Rotterdam', 'Leiden', 'Zoetermeer'];
const MAX_RENT = 1500;

const TIME_ZONE = 'Europe/Amsterdam';
const START_HOUR = 7;
const END_HOUR = 23;
const REFRESH_MINUTES = [5, 15];
const MIN_SETTLE_MS = 10000;
const MAX_SETTLE_MS = 30000;

```

预算判断只使用主租金，脚本不会判断房补、收入或学生资格。修改预算后会重新计算资格并保留成功通知记录。`STORAGE_PREFIX` 通常不改；新前缀代表另一套 Telegram 配置和历史。
